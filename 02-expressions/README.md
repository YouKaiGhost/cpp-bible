# 第 2 章 · 表达式、值类别与求值

> **卷一 · 语言**　|　前置知识：第 0–1 章　|　建议用时：50 分钟

> 类型决定对象能做什么，表达式决定对象什么时候做。

第 1 章把对象摆在了内存里。这一章让对象开始运动：加法、比较、赋值、自增、位运算、条件表达式。看起来都是老熟人，但 C++ 在这里加了两样 C 没有的东西：**引用**和**值类别**。它们会决定一个表达式能不能被修改、能不能被绑定、会不会产生临时对象。

这一章只讲语言层面的表达式规则。运算符重载的细节留到第 7 章，标准库的格式化输出留到以后。

## 2.2 表达式、语句与副作用

**表达式**是能求出一个值的构造。**语句**是执行一个动作的完整单位。表达式加上分号，通常就成了表达式语句：

```cpp
x + 1;      // 表达式语句：算出一个值，然后丢掉
x = x + 1;  // 表达式语句：算出赋值结果，然后丢掉
```

第一行合法但没用；第二行有**副作用**（side effect）——它修改了 `x` 的值。副作用是表达式求值过程中对对象状态的改变，包括赋值、自增、函数调用、输入输出等。

C++ 的表达式求值可以拆成两部分：

- **值计算**（value computation）：算出表达式的值；
- **副作用**（side effect）：修改对象、调用函数、读写流。

大部分麻烦都来自“副作用发生的顺序”。第 2.10 节会集中处理。

## 2.3 算术运算符

```cpp
int a = 7;
int b = 3;

a + b;   // 10
a - b;   // 4
a * b;   // 21
a / b;   // 2：整数除法，向零截断
a % b;   // 1
```

几个必须记住的规则：

- 两个整数相除，结果还是整数，小数部分被丢弃。`7 / 2` 是 `3`，不是 `3.5`。
- 除法的截断方向是**向零**：`-7 / 3` 是 `-2`，`-7 % 3` 是 `-1`。
- `%` 只能用于整数类型（C++ 标准库另有 `std::fmod` 处理浮点）。
- 除数为 0 是**未定义行为**，不是“抛异常”，也不是“返回 0”。
- 有符号整数溢出是**未定义行为**；无符号整数溢出是**有定义的回绕**。

如果想得到浮点除法，至少要让一个操作数是浮点：

```cpp
double result = static_cast<double>(a) / b;  // 3.5
```

`static_cast<double>(a) / b` 会先把 `a` 转成 `double`，再做浮点除法。写成 `static_cast<double>(a / b)` 就晚了：整数除法已经发生。

### 浮点的特殊值

浮点运算可能产生无穷大（infinity）和 NaN（not a number）：

```cpp
double zero = 0.0;
double inf = 1.0 / zero;   // 如果实现支持 IEEE 754，得到 inf
double nan = zero / zero;  // NaN
```

但这是浮点实现的行为，不是整数除零。整数除零始终是 UB。

## 2.4 值类别：lvalue、prvalue、xvalue

这是 C++ 表达式理论里最重要的一个分类。标准定义了三类：

| 值类别 | 英文 | 直觉 | 例子 |
|--------|------|------|------|
| 左值 | lvalue | 有名字、有地址、可以取地址 | 变量 `x`、`*p`、`a[i]` |
| 纯右值 | prvalue | 纯粹的值，通常没有名字 | `42`、`x + 1`、`std::string("hi")` |
| 将亡值 | xvalue | 有身份但资源可以被“搬走” | `std::move(x)`、`static_cast<T&&>(x)` |

再把它们合并成两个更大的类别：

- **泛左值**（glvalue）= lvalue + xvalue：有身份（identity），能确定是哪个对象。
- **右值**（rvalue）= prvalue + xvalue：可以绑定到右值引用，通常表示“可以移动”。

为什么要分这么细？因为 C++11 的移动语义依赖它：

```cpp
int x = 1;
int &lref = x;             // 左值引用绑定左值
int &&rref = 42;           // 右值引用绑定纯右值
int &&moved = std::move(x); // std::move 把 x 转成 xvalue
```

`std::move(x)` 本身**不移动任何东西**。它只是一个 `static_cast<T&&>(x)`，把表达式从 lvalue 变成 xvalue，告诉编译器“这个对象的资源可以被搬走”。真正的移动发生在移动构造函数或移动赋值里。

`decltype` 可以帮我们观察值类别：

```cpp
int x = 1;
decltype(x) a = 2;       // int
decltype((x)) b = x;     // int &：加括号后是左值表达式
decltype(std::move(x)) c = 0; // int &&
```

`decltype(x)` 看的是**名字**的类型；`decltype((x))` 看的是**表达式**的值类别。多一层括号，结果就变了。

值类别还会影响重载决议：一个函数可以同时提供 `f(T&)` 和 `f(T&&)`，左值选前者，右值选后者。第 7 章讲移动构造时会用到。

## 2.5 关系、相等与逻辑

```cpp
a < b;    // 小于
a <= b;   // 小于等于
a > b;    // 大于
a >= b;   // 大于等于
a == b;   // 等于
a != b;   // 不等于
```

关系运算符的结果是 `bool`。不要把 `=` 和 `==` 搞混：

```cpp
if (x = 1) { ... }   // 赋值，条件恒为 true（除非赋 0）
if (x == 1) { ... }  // 比较
```

现代编译器通常会对 `if (x = 1)` 给出警告；不要依赖这个警告，写的时候就要看清。

### 逻辑运算符与短路

```cpp
a && b;   // 逻辑与
a || b;   // 逻辑或
!a;       // 逻辑非
```

`&&` 和 `||` 会**短路求值**：

- `a && b`：如果 `a` 为假，`b` 不求值。
- `a || b`：如果 `a` 为真，`b` 不求值。

这不仅是优化，也是语义的一部分：

```cpp
if (pointer != nullptr && *pointer > 0) {
    // 只有 pointer 非空时才会解引用
}
```

如果 `&&` 不短路，这个惯用法就会崩溃。短路还保证左侧先于右侧求值，这一点在带副作用的表达式里很重要。

`!` 把操作数转成 `bool` 再取反。`!0` 是 `true`，`!42` 是 `false`。

逻辑运算符和位运算符不要混：

```cpp
2 && 4   // true（两者都非零）
2 & 4    // 0（按位与）
2 || 4   // true
2 | 4    // 6（按位或）
```

## 2.6 位运算

位运算直接操作整数的二进制表示：

```cpp
x & y;    // 按位与
x | y;    // 按位或
x ^ y;    // 按位异或
~x;       // 按位取反
x << n;   // 左移
x >> n;   // 右移
```

规则与陷阱：

- 操作数必须是整数类型（包括 `char`、`bool`、枚举）。
- 移位量必须是非负的，并且小于操作数类型的位宽；否则是 UB。
- 左移有符号负数、左移导致有符号溢出，都是 UB。
- 右移有符号负数由实现定义（算术右移或逻辑右移）。
- 无符号整数的移位和回绕都有明确定义。
- `~x` 的结果类型是提升后的类型；对 `unsigned` 取反会得到很大的数。

位运算常用于标志位：

```cpp
constexpr unsigned READ = 1u << 0;
constexpr unsigned WRITE = 1u << 1;
constexpr unsigned EXEC = 1u << 2;

unsigned permissions = READ | WRITE;
bool can_read = (permissions & READ) != 0;
```

这里用 `1u` 而不是 `1`，是为了让移位在无符号类型里进行，避免有符号左移的边界问题。

## 2.7 自增、自减与赋值

```cpp
int i = 5;
int a = ++i;  // 先加，再取值：i == 6, a == 6
int b = i++;  // 先取值，再加：b == 6, i == 7
```

- `++i` 是**前自增**，返回自增后的左值引用。
- `i++` 是**后自增**，返回自增前的值（纯右值），副作用在稍后发生。
- `--` 同理。

对内置类型，编译器通常会把 `i++` 优化成和 `++i` 一样；但对类类型，后自增需要保留旧值，可能多一次拷贝。泛型代码里常写 `++it` 而不是 `it++`，就是这个原因。

赋值运算符是右结合的：

```cpp
a = b = c;   // 等价于 a = (b = c)
```

复合赋值：

```cpp
x += 5;   // x = x + 5
x -= 3;
x *= 2;
x /= 4;
x %= 3;
x <<= 1;
x &= mask;
```

复合赋值只求值左侧一次，并且对类类型可能比 `x = x + y` 更高效。

**不要写**：

```cpp
i = i++;       // 不同标准版本规则不同，不要写
a[i] = i++;    // 依赖 i 的读写顺序，不要写
```

这类代码在不同标准版本里可能从 UB 变成有定义，或者反过来；即使某条规则在某个版本里有定义，这种代码也无法让读者一眼看懂。可读性本身就是正确性的一部分。

## 2.8 条件运算符与逗号运算符

条件运算符是 C++ 里唯一的三元运算符：

```cpp
int max = (a > b) ? a : b;
```

规则：

- 先求值条件，条件为真选第二个操作数，为假选第三个。
- 只有被选中的分支会被求值，另一个分支不产生副作用。
- 两个分支的类型会进行转换，得到一个共同类型。`true ? 1 : 2.5` 的结果是 `double`。

逗号运算符：

```cpp
int x = (a++, b++);
```

它从左到右求值，丢弃左边表达式的值，返回右边表达式的值。上面的 `x` 是 `b++` 的旧值。

逗号运算符很容易和函数参数、初始化列表里的逗号混淆。除了循环的增量部分，现代 C++ 很少需要它；不要为了“紧凑”而滥用。

## 2.9 优先级与结合性

优先级决定“先算谁”，结合性决定“同级从左还是从右”。

| 优先级 | 运算符 | 结合性 |
|--------|--------|--------|
| 高 | `::` | 左 |
| | `()` `[]` `.` `->` `++` `--`（后缀） | 左 |
| | `!` `~` `++` `--`（前缀） `+` `-`（一元） `*` `&` `sizeof` | 右 |
| | `.*` `->*` | 左 |
| | `*` `/` `%` | 左 |
| | `+` `-` | 左 |
| | `<<` `>>` | 左 |
| | `<=>`（C++20） | 左 |
| | `<` `<=` `>` `>=` | 左 |
| | `==` `!=` | 左 |
| | `&` | 左 |
| | `^` | 左 |
| | `\|` | 左 |
| | `&&` | 左 |
| | `\|\|` | 左 |
| | `?:` | 右 |
| | `=` `+=` 等 | 右 |
| | `,` | 左 |

不要背整张表。记住几个高频陷阱就够了：

- `*p++` 是 `*(p++)`，不是 `(*p)++`。
- `a & 1 == 0` 是 `a & (1 == 0)`，不是 `(a & 1) == 0`。比较运算符优先级高于位与。
- `a << 1 + 1` 是 `a << (1 + 1)`，不是 `(a << 1) + 1`。加法优先级高于移位。
- `*p.f` 是 `*(p.f)`，不是 `(*p).f`；要解引用再取成员，写 `(*p).f` 或 `p->f`。

不确定时加括号。括号不丢人，读错代码才丢人。

## 2.10 求值顺序

优先级不等于求值顺序。`f() + g()` 里，`+` 的优先级明确，但 `f()` 和 `g()` 谁先执行，标准没有规定。

C++17 明确保证了一部分顺序：

1. **赋值**：右侧先于左侧求值，赋值副作用在两侧值计算之后。
2. **移位**：`<<` 和 `>>` 的左侧先于右侧求值。
3. **下标**：`a[b]` 中 `a` 先于 `b` 求值。
4. **函数调用**：后缀表达式先于参数求值；参数之间的顺序是**不确定顺序**（indeterminately sequenced），但不是交错执行。
5. **`&&` / `||`**：左侧先求值，并按短路规则决定是否求值右侧。
6. **条件运算符**：条件先求值，然后只求值一个分支。
7. **逗号**：左侧先于右侧。
8. **列表初始化**：花括号里的元素从左到右求值。

“不确定顺序”意味着：一个参数的所有求值必须在另一个参数开始之前完成，但哪个参数先开始，标准不规定。不同编译器、不同优化级别可能不同。

看一个例子：

```cpp
int f();
int g();

int x = f() + g();       // f 和 g 的顺序未指定
std::cout << f() << g(); // C++17 起：f 先于 g
```

第二行之所以确定，是因为 `<<` 的左侧先于右侧求值，而链式表达式是左结合的。

还有两个容易混淆的概念：

- **未指定顺序**（unspecified order）：标准允许几种顺序，但每次执行必须选一种，行为不是 UB。
- **未定义行为**（undefined behavior）：标准不规定任何结果，程序可能做任何事。

`f() + g()` 是未指定顺序，不是 UB（前提是 `f`、`g` 不修改同一对象）。`i = i++` 这类在同一表达式中对同一标量多次无序修改的写法，才可能落入 UB。

## 2.11 类型转换

算术表达式里的类型转换主要有三层：

1. **整数提升**：`bool`、`char`、`short` 等小类型提升为 `int`（或 `unsigned int`）。
2. **寻常算术转换**：两个操作数转换成共同类型，通常向更宽的类型、无符号类型转换。
3. **显式转换**：`static_cast`、`const_cast`、`reinterpret_cast`、`dynamic_cast`。

例子：

```cpp
unsigned char c = 300;        // 按模 256 回绕，结果是 44
unsigned int u = 0u - 1u;     // UINT_MAX，有定义
int i = static_cast<int>(3.9); // 3
double d = static_cast<double>(7) / 2; // 3.5
```

有符号和无符号混合比较是经典陷阱：

```cpp
int negative = -1;
unsigned int one = 1;
// negative < one 会把 negative 转成很大的无符号数，结果为 false
```

C++20 提供了 `std::cmp_less` 等工具来安全比较不同符号的整数；C++17 里只能显式转换或避免混合比较。

## 2.13 常见陷阱

| 写法 | 问题 | 建议 |
|------|------|------|
| `7 / 2` 期望 `3.5` | 整数除法截断 | 至少一个操作数转成浮点 |
| `x / 0` | 除零，UB | 运算前检查 |
| `a & 1 == 0` | 实际是 `a & (1 == 0)` | 写 `(a & 1) == 0` |
| `*p++` | 是 `*(p++)`，指针先自增 | 明确写 `(*p)++` 或 `*(p++)` |
| `int` 溢出 | 有符号溢出是 UB | 用无符号或更宽类型，并检查边界 |
| `char` 参与算术 | 先提升为 `int`，结果可能超出 `char` | 赋值前检查范围 |
| `unsigned` 减法 | 下溢回绕成很大的数 | 先判断大小，或用有符号类型 |
| `f() + g()` | 求值顺序未指定 | 有依赖时拆成两条语句 |
| `i = i++` | 同一表达式多次修改同一对象 | 不要写 |
| `sizeof(x++)` | 操作数通常不求值 | 不要依赖副作用 |

## 2.14 语法卡片

| 术语 | 一句话定义 | 本章例子 |
|------|------------|----------|
| 表达式 | 能求出一个值的构造 | `a + b` |
| 副作用 | 求值过程中对对象状态的改变 | `++i` |
| 左值 | 有身份、可取地址的表达式 | `x`、`*p` |
| 纯右值 | 纯粹的值，通常没有名字 | `42`、`a + b` |
| 将亡值 | 有身份但资源可被移动的表达式 | `std::move(x)` |
| 短路求值 | 逻辑运算符按左侧结果跳过右侧 | `p && *p` |
| 整数提升 | 小整数类型先转成 `int` | `char + char` |
| 寻常算术转换 | 两个操作数转成共同类型 | `int + unsigned` |
| 未指定顺序 | 标准允许多种顺序，不是 UB | `f() + g()` |
| 未定义行为 | 标准不规定任何结果 | `1 / 0`、有符号溢出 |

## 2.15 练习

1. **整数除法**：分别计算 `7 / 2`、`-7 / 2`、`7 / -2`、`-7 / -2`，以及对应的 `%`。总结截断方向。
2. **浮点**：用 `static_cast<double>` 改写 `7 / 2`，得到 `3.5`。再试 `static_cast<double>(7 / 2)`，解释为什么结果不同。
3. **短路**：写一个函数 `bool check(int)`，打印参数并返回真假。用 `&&` 和 `||` 组合调用，观察哪些调用没有发生。
4. **值类别**：用 `decltype` 和 `std::is_same_v` 验证 `decltype(x)`、`decltype((x))`、`decltype(std::move(x))` 的类型。
5. **优先级**：不运行程序，先判断 `*p++`、`a & 1 == 0`、`a << 1 + 1` 的含义，再写代码验证。
6. **求值顺序**：写两个会打印的函数 `f()`、`g()`，分别放进 `f() + g()` 和 `std::cout << f() << g()`，比较输出顺序，并解释标准保证了什么。
7. **位标志**：用 `1u << n` 定义四个权限位，实现 `has(permissions, bit)` 和 `add(permissions, bit)`。
8. **破坏实验**：把 `0u - 1u` 改成 `0 - 1`，打印结果；再把 `int` 的最大值加 1，观察编译器警告或运行结果（注意：这是 UB，不要在产品代码里做）。

届时，`std::cout << f() << g()` 不只是一条输出语句，而会成为你观察“顺序”和“作用域”的入口。
