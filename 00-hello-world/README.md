# 第 0 章 · Hello, World!

> **卷一 · 语言**　|　前置知识：无　|　建议用时：25 分钟

每个 C++ 教材都以同一个程序开始。不是因为它简单到没有东西可讲，而是因为它小到可以把每个字符都讲清楚。

这一章只做一件事：让程序向标准输出写下一行字，然后以“成功”结束。但它已经包含了 C++ 程序的全部骨架：一个翻译单元、一个入口函数、一条表达式语句、一个返回值。

## 0.2 完整程序

```cpp
#include <iostream>

int main()
{
    std::cout << "Hello, World!\n";
    return 0;
}
```

仓库里的 [`hello.cpp`](hello.cpp) 是同一程序的注释版。可以先读这份没有注释的骨架，再打开注释版，看每个部分如何落在源码里。

## 0.3 编译与运行

在本章目录 `00-hello-world/` 中执行：

```sh
c++ -std=c++17 -Wall -Wextra -Wpedantic hello.cpp -o hello
./hello
```

你应该看到：

```text
Hello, World!
```

这条命令的每个部分都在说话：

| 片段 | 含义 |
|------|------|
| `c++` | C++ 编译器驱动程序。通常指向 GCC 的 `g++` 或 Clang 的 `clang++`。 |
| `-std=c++17` | 选择 ISO C++17 标准。本书以此为基础。 |
| `-Wall -Wextra` | 打开常用警告。警告不是噪音，是编译器在提前救你。 |
| `-Wpedantic` | 对不符合标准的地方给出诊断，阻止方言悄悄混进来。 |
| `hello.cpp` | 输入的源文件。 |
| `-o hello` | 指定输出文件名为 `hello`。 |

在仓库根目录也可以直接：

```sh
make run
```

编译成功只说明“翻译”成功；运行成功才说明程序真的做了你想让它做的事。

## 0.4 从源文件到进程

一个 C++ 程序不是从 `main` 开始被“解释”的。在 `main` 之前，源文件要经过一条流水线：

```text
hello.cpp
   │  预处理：展开 #include，处理宏，注释变成空白
   ▼
预处理后的翻译单元
   │  编译：检查语法和语义，实例化模板，生成汇编 / 目标代码
   ▼
hello.o
   │  链接：加入启动代码，找到 std::cout 和 operator<< 的实现
   ▼
hello（可执行文件）
   │  装载：操作系统把程序放进内存
   ▼
进程从启动代码进入 main
```

这条流水线解释了两类不同的错误：

- **编译错误**：编译器读不懂你的源代码。例如少了分号、括号不配对、模板参数不匹配。
- **链接错误**：每个源文件都翻译成功了，但最后拼不起来。例如 `main` 拼成了 `Main`，或者调用了只声明、没定义的函数。

后面我们会反复用到这个区分。现在只需要记住：**能编译，不等于能链接；能链接，不等于行为正确。**

C++ 还有一条 C 没有的支线：**模板实例化**。模板本身不是机器码，编译器在看到具体类型时才会生成代码。第 9 章会把这条支线展开。

## 0.5 逐行解剖

### 注释：写给人的空白

C++ 继承了 C 的两种注释：

```cpp
/* 块注释，可以跨行 */
// 行注释，到本行末尾结束
```

注释不是程序行为的一部分。在翻译的早期阶段，每条注释会被替换成一个空格，然后再进入后续处理。因此：

- 注释可以出现在大多数空白可以出现的地方。
- 块注释**不能嵌套**。第一个 `*/` 就会结束它。
- 不要用块注释去“屏蔽”一段本身含有 `*/` 的代码，否则注释会提前结束。
- C++ 的 `//` 从 C++98 起就是标准的一部分，不像 C 那样要等到 C99。

注释是给未来的自己看的。好的注释解释“为什么”，而不是把代码翻译成自然语言。

### `#include <iostream>`：借一张声明

```cpp
#include <iostream>
```

这是**预处理指令**，不是 C++ 语句。它有三个容易记错的细节：

1. 它以 `#` 开头，在编译之前由预处理器处理。
2. 它**不以分号结尾**。加上分号反而可能触发“指令末尾有多余记号”的诊断。
3. 尖括号里的 `iostream` 是头文件名，不是字符串字面量。

`iostream` 是 C++ 标准库的头文件，里面声明了标准输入输出流，其中就包括 `std::cout`、`std::cin`、`std::cerr` 和 `operator<<` 的一系列重载。这一行把它的内容引入当前翻译单元，让编译器在此后知道：

```cpp
namespace std {
    extern ostream cout;   // 简化后的声明
}
```

你现在不需要读懂 `ostream` 的完整定义。只需要知道：`std::cout` 是一个**对象**，不是函数；它代表标准输出流。`<<` 也不是“左移”那么简单，它在 iostream 里被重载成了“把右边的值写进流”的运算符。

这里有一个必须分清的概念：

- **头文件提供声明**：告诉编译器“有这个对象/函数，长这样”。
- **标准库提供定义**：真正的实现和对象存储由运行库提供，链接阶段才会被找到。

所以 `#include <iostream>` 不是“把 `cout` 搬进程序”，而是“把 `cout` 的名片交给编译器”。

### `int main()`：程序的入口

```cpp
int main()
```

这是一个**函数定义**的开头。把它拆开：

| 片段 | 名称 | 含义 |
|------|------|------|
| `int` | 返回类型 | `main` 把一个整数返回给宿主环境。 |
| `main` | 函数名 | C++ 标准约定的程序入口名。它不是关键字。 |
| `()` | 参数列表 | 表示这个函数不接受参数。 |
| `{ ... }` | 函数体 | 一个复合语句，也就是一个块。 |

关于 `main`，有几条现在就该建立的直觉：

- C++ 区分大小写。`main`、`Main`、`MAIN` 是三个不同的名字；只有 `main` 是入口。
- 标准规定 `main` 的返回类型是 `int`。`void main()` 不是标准 C++，即使某个编译器放过了它。
- 标准明确给出两种主要形式：`int main()` 和 `int main(int argc, char *argv[])`。后者用于接收命令行参数，第 4 章会讲；实现也可以支持其他形式，但那些形式不可移植。
- C++ 的 `int main()` 与 C 的 `int main(void)` 等价：空参数列表在 C++ 里就是“没有参数”，没有 C 里“参数未指定”的歧义。

严格地说，操作系统并不会直接“调用 main”。链接器会加入一段启动代码，由启动代码准备好运行环境，再调用 `main`，最后把 `main` 的返回值交给运行环境，成为进程的退出状态。

### `std::cout << "Hello, World!\n";`：一条表达式语句

```cpp
std::cout << "Hello, World!\n";
```

这是一条**表达式语句**。它由两部分组成：

```text
std::cout << "Hello, World!\n"   +   ;
            表达式                  分号
```

先看表达式：

- `std::cout` 是标准输出流对象。`std::` 是命名空间限定符，`cout` 是名字。
- `<<` 是**流插入运算符**。在这里它被重载为“把右边的值写到左边的流里”。
- `"Hello, World!\n"` 是**字符串字面量**，类型是 `const char[15]`，在表达式中会退化为 `const char *`。

字符串字面量不是“随便一段文字”，它有精确的内部表示。它的内容依次是：

```text
'H' 'e' 'l' 'l' 'o' ',' ' ' 'W' 'o' 'r' 'l' 'd' '!' '\n' '\0'
```

最后那个 `\0` 是空字符（null character），用来标记 C 风格字符串的结束。它不是你手写进去的，而是字符串字面量自动带的。所以：

```cpp
sizeof("Hello, World!\n") == 15
```

13 个字符（含空格和逗号），加 1 个换行符，加 1 个空字符，正好 15。

`\n` 是**转义序列**：用一个反斜杠加一个字母，表示一个特殊字符或不可见字符。常见的几个：

| 写法 | 含义 |
|------|------|
| `\n` | 换行（newline） |
| `\t` | 水平制表符（tab） |
| `\\` | 一个反斜杠本身 |
| `\"` | 一个双引号本身 |
| `\0` | 空字符 |
| `\x41` | 十六进制值为 41 的字符（`A`） |

注意：`\n` 是一个字符，不是两个字符。`std::cout` 也不会自动帮你换行；换行是你明确写进字符串里的。

为什么不写 `std::cout << std::endl;`？`std::endl` 会输出换行并**刷新缓冲区**。对一行普通输出，`'\n'` 已经足够；频繁 `std::endl` 可能带来不必要的刷新。先记住：`'\n'` 是换行，`std::endl` 是“换行 + flush”。

`<<` 表达式本身有一个返回值：它返回左边的流对象的引用。因此可以链式写：

```cpp
std::cout << "a" << "b" << '\n';
```

这等价于：

```cpp
((std::cout << "a") << "b") << '\n';
```

链式调用能成立，是因为每次 `<<` 都返回 `std::ostream &`。第 2 章会讲运算符和求值顺序，第 7 章会讲运算符重载。

最后，分号把表达式变成语句：

```cpp
std::cout << "Hello, World!\n";   // 表达式语句
```

分号不是“分隔符”，而是**语句结束符**。少一个，编译器就会在下一个记号处抱怨。

### `return 0;`：正常退出

```cpp
return 0;
```

这是**返回语句**。它做两件事：

1. 结束当前函数的执行。
2. 把表达式 `0` 的值返回给调用者。

对 `main` 来说，调用者是启动代码；这个值最终成为进程的退出状态。约定是：

- `0` 表示成功。
- 非 `0` 表示失败。标准库在 `<cstdlib>` 里定义了 `EXIT_SUCCESS` 和 `EXIT_FAILURE` 两个宏，分别表示成功和失败。
- 具体非零值如何被操作系统解释，由实现定义。Unix shell 通常只保留低 8 位，所以 `return 256;` 在 shell 里可能看起来是 `0`。

一个常被忽略的细节：C++ 标准规定，如果 `main` 执行到右花括号 `}`，效果等同于返回 `0`。所以删掉 `return 0;`，程序仍然以成功状态结束。但显式写出来，意图更清楚，也不依赖这条“隐式返回”规则。

在 Unix 终端里可以查看上一条命令的退出状态：

```sh
./hello
echo $?
```

Windows 命令提示符里则是：

```bat
hello.exe
echo %ERRORLEVEL%
```

## 0.6 标点、空白与大小写

C++ 的语法对空白相当宽容，但对标点非常挑剔。

- **分号 `;`** 结束一条语句或一个声明。`#include` 和函数定义的头不属于这一类，不要机械地加分号。
- **花括号 `{ }`** 把若干声明和语句组成一个块。块也构成作用域，后面讲变量时会长出牙齿。
- **空白和换行**在大多数地方只是分隔记号，不影响语义。缩进是给人看的，编译器不看。
- **但空白不能省在记号内部**：`int main` 不能写成 `intmain`；字符串里的空格更是数据的一部分。
- **C++ 区分大小写**：`std::cout` 和 `std::Cout` 不同，`main` 和 `Main` 不同。
- **只能用 ASCII 标点**：中文的 `；`、`，`、`（）`、`“”` 都是不同的 Unicode 字符，不是 C++ 的标点。编译器看到它们，通常会在它们出现的位置报错（`stray`、`expected` 一类）。

初学阶段相当一部分“诡异错误”都来自最后两条：大小写和全角标点。

## 0.7 故意改坏它

学习语法最快的方式之一，是故意违反它，然后读编译器的诊断。下面每个实验都建议真的做一遍。

| 改动 | 你大概会看到 | 它在说什么 |
|------|--------------|------------|
| 删掉 `std::cout << ...;` 后的分号 | `expected ';' before 'return'` | 编译器常在“下一个记号”处发现上一句没结束。 |
| 删掉 `#include <iostream>` | `'cout' is not a member of 'std'` | 编译器没见过 `std::cout` 的声明。 |
| 把 `main` 写成 `Main` | `undefined reference to 'main'` | 编译通过了，但链接器找不到入口。 |
| 把分号写成中文 `；` | `expected ';' before '；'`（或 stray 字节一类的信息） | 全角标点不是 C++ 标点。 |
| 删掉 `return 0;` | 仍能运行，退出码为 0 | `main` 执行到 `}` 会隐式返回 0。 |
| 把 `"..."` 改成中文引号 | `stray` / `expected` 一类错误 | 中文引号不是字符串字面量的定界符。 |
| 把 `std::cout` 写成 `cout` | `'cout' was not declared in this scope` | 名字不在当前作用域；`std` 限定不能省。 |

读诊断时，先看**第一条错误**。后面的错误经常是第一条造成的连锁反应。看三样东西：

1. 文件名和行号；
2. 列号和插入符 `^` 指向的位置；
3. 错误信息的最后一句，以及它给出的 `note`。

编译器指的位置不一定是“真正错的地方”。少了分号时，它往往指向下一行的第一个记号，因为直到那里它才发现上一句没有结束。模板错误会更长，第 9 章会给一套阅读方法。

## 0.8 语法卡片

| 术语 | 一句话定义 | 本章例子 |
|------|------------|----------|
| 预处理指令 | 编译前由预处理器执行的行 | `#include <iostream>` |
| 函数定义 | 给出返回类型、函数名、参数和函数体 | `int main() { ... }` |
| 复合语句 / 块 | 一对花括号包围的声明和语句 | `{ ... }` |
| 命名空间 | 给名字划分作用域的机制 | `std::cout` |
| 表达式 | 可以求出一个值的构造 | `std::cout << "Hello"` |
| 表达式语句 | 表达式后加分号形成的语句 | `std::cout << ...;` |
| 流插入运算符 | 把值写入输出流的运算符 | `<<` |
| 字符串字面量 | 双引号包围的字符序列，末尾自动带空字符 | `"Hello, World!\n"` |
| 转义序列 | 用反斜杠表示特殊字符 | `\n` |
| 返回语句 | 结束函数并把值交给调用者 | `return 0;` |

一个必须反复强调的区分：**`std::cout` 和 `<<` 不是 C++ 语法的一部分，它们是标准库提供的对象和运算符重载。** 本章真正属于语言的东西，是函数调用/运算符表达式、字符串字面量、分号和返回语句。把“语言”与“库”分开看，是这套教材的一条主线。

## 0.9 练习

1. **改名**：把 `Hello, World!` 换成你的名字，重新编译运行。只改字符串内容，不要动引号和分号。
2. **两行**：用两个 `std::cout` 输出两行；再改成一个 `std::cout`，用两个 `\n` 完成。比较哪种写法更清楚。
3. **退出码**：删掉 `return 0;`，编译运行，然后用 `echo $?`（Unix）或 `echo %ERRORLEVEL%`（Windows）查看退出码。再改成 `return 7;`，观察变化。解释为什么。
4. **删头文件**：删掉 `#include <iostream>`，编译，读第一条诊断；恢复。然后用 `-Werror` 再编译一次，观察警告如何变成错误。
5. **转义**：让程序输出 `C:\code` 和一行带双引号的 `"Hello"`。提示：`\\` 和 `\"`。
6. **非标准入口**：把 `int main()` 改成 `void main()`，加上 `-Wpedantic` 编译，读诊断。查一查为什么标准要求 `main` 返回 `int`。
7. **链式输出**：把一行拆成三个 `<<`，再加一个 `std::endl`，观察输出和刷新行为。查一查 `std::endl` 与 `'\n'` 的区别。
8. **破坏实验**：任选一个分号删掉，记录编译器报告的行号和列号，判断它真正想说的是哪一行。

做完练习 3，你会第一次直接看到“返回值”如何离开程序，变成 shell 能观察到的状态。这是 C++ 程序与操作系统之间最细的一根线。

## 0.10 本章没有讲什么

为了保持“只讲语法和特性”的边界，本章刻意没有展开：

- `std::cout` 的格式化输出（宽度、精度、进制、`std::format`）；
- 标准输入输出缓冲、文件流、文本模式与二进制模式；
- `argc` / `argv` 和命令行参数；
- `std::cin`、`std::cerr`、`std::clog` 的差别；
- 目标文件、符号表、链接器脚本；
- 字符串字面量的存储期，以及修改它的未定义行为；
- 模块（modules）与头文件的替代关系。

这些会在后续章节或“标准库边界”专题里出现。现在，先把 Hello World 的每个字符都握稳。
